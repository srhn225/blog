# Hane 写作台

在 Finder 中双击仓库里的 `启动写作台.command`，或在仓库中运行：

```sh
npm ci
npm run writer
```

打开 <http://127.0.0.1:4318>。关闭启动服务的终端后，写作台停止运行。

写作台可新建文章、编辑已有文章、选择或新建分类、添加标签、设置日期、作者和封面，支持 Markdown 编辑、预览、分屏、专注模式和导出。日期使用北京时间。作者会同时写入 Butterfly 的 `copyright_author`，确保页面上的署名一致。

输入会自动保存到 `.writer/drafts/`，该目录已被 Git 忽略，不会部署到公开博客。尚未完成保存的修改还会备份到当前浏览器。编辑已有文章时会保留未在界面展示的 YAML 信息；没有修改的文章会保留原文件字节。

点击“检查发布”会在临时目录生成完整博客并检查文章页面，不推送。点击“发布文章”会保存当前内容、读取远端最新版本、检查冲突、独立构建，只提交选中的文章，并推送到 `origin/main`。现有 `.github/workflows/pages.yml` 自动构建和部署。界面会持续显示 GitHub Actions 结果，最后核对在线文章的标题和正文。

文章推送后，写作台尝试把本地分支快进到远端。遇到本地冲突时会保留本地文件，显示同步提示；远端发布和本地同步的结果分别记录。不会运行 `hexo deploy`，不会自动加入其他文件、强制推送或覆盖远端新版本。公开文章在界面中编辑时先保存为本地草稿，点击发布才更新 GitHub。删除草稿只删除本地副本。

服务仅监听 `127.0.0.1`，校验请求来源和随机会话令牌；GitHub 发布使用电脑上已经配置的 Git/SSH 身份。无需在网页里填写 GitHub 密码或 token。需要 `origin` 远端、Git 的 `user.name` / `user.email` 和对发布分支的推送权限。部署状态通过公开 GitHub API 查询；遇到限流或断网，文章已推送的状态会保留，可打开 Actions 或重新查询。重启服务后，发布历史也会保留。

这是本地写作界面；在线版本是现有博客及发布后的文章：<https://srhn225.github.io/blog/>。

可通过 `WRITER_PORT=4320 npm run writer` 修改端口，通过 `WRITER_BRANCH` 修改发布分支。发布分支必须与 GitHub Actions 触发分支一致。`WRITER_REPO_DIR` 仅用于开发验证其他 Hexo 仓库。

快捷键：`⌘S` / `Ctrl+S` 保存，`⌘N` / `Ctrl+N` 新建，正文中 `⌘B` / `Ctrl+B` 加粗，`Esc` 退出专注模式。

运行 `npm run test:writer` 检查草稿保存、冲突处理、来源校验、YAML 保留和发布隔离行为。
